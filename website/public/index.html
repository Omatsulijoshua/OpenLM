01 / THE IDEA

A bigger model.
A smaller ask
of each device.

A large model can outgrow one machine’s memory. OpenLM gives it somewhere else to go.

OpenLM distributes model layers across a local network. Turn on Shared chat on the model host, then join with the invite link from another device to sync saved text conversations. One device at a time has primary chat control; take over from a laptop, desktop, tablet or phone. The loaded model stays on its original host while you move between screens.

The aim is one continuous workspace across laptop, desktop, tablet and phone, not a phone-only remote control. llama.cpp’s GGUF and RPC path handles distributed inference underneath.

04 / TRY IT YOURSELF

Start with
what you have.

Get OpenLM on GitHub ↗

  1. On Windows, download and open the app.

    Get the latest Windows portable ZIP from GitHub Releases ↗. Extract the ZIP, keep its files together, then launch openlm.exe.

  2. Put your devices on the same network.

    Install OpenLM on participating devices. Use a trusted local network with enough available memory across your machines.

  3. Give each device a role.

    Open Settings → Phone cluster. Choose Worker on devices contributing resources. Choose Master on the device coordinating the model. Pair workers using their QR code or connection link.

  4. Load a GGUF. Start a conversation.

    Choose a compatible model on the coordinator. OpenLM checks memory and plans the split before loading. Keep workers reachable while you chat.

A FEW PRACTICAL NOTES
Does the model stay local?

In local GGUF cluster mode, inference runs on your participating devices. Workers exchange computation over your LAN. Model downloads need a connection, and choosing a cloud provider sends requests to that provider. Use RPC only among trusted devices; do not expose worker ports to the public internet.

Can I move the chat between devices?

On the model host, start Shared chat and join from the other device using its invite link. Connected devices sync saved text conversations. Tap Take over in the chat screen to make that device the active chat controller; only one device can hold that control at a time. Inference continues on the original model host, and image attachments are not synced yet. Use the invite only on a trusted network.

Can I mix a phone, a Mac and a Windows PC?

The cluster service supports Android, iOS, macOS, Windows and Linux as coordinator or worker. Actual model fit and backend compatibility depend on the build and devices. Keep worker apps running; background limits, heat and battery management can interrupt a session.

Will a 30B model run on my setup?

Check the exact GGUF file size, available RAM and context requirements. Parameter count alone cannot answer this. Our illustration is a capacity example, not a guarantee for a particular model or device. Start with a smaller model, then measure memory use and responsiveness.

Is this training? Does every model work?

This is inference: generating responses from an already trained model. The illustrated distributed path uses GGUF through llama.cpp RPC. LiteRT models are not split across the cluster by this path.

What makes a cluster slow?

Activations cross the network as layer groups execute. Network delays, memory bandwidth and a slow worker can outweigh the benefit of adding hardware. A wired network can help, but only measurements on your own setup establish performance.
